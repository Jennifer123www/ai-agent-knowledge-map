A practical definition

Agent 不是“会聊天的模型”

更准确地说，它是一个以目标为中心、能观察、判断、行动、复盘的系统。模型负责生成候选方案，系统负责把方案变成可控的执行。

01 Observe感知任务

读取用户目标、环境状态、文件、网页或传感器信号。

02 Ground补齐依据

检索知识、读取记忆、调用数据接口，减少“凭感觉回答”。

Agent Loop规划 · 推理 · 路由
03 Act调用能力

选择 Skill、工具或远程 Agent，执行可验证的动作。

04 Learn记录与评估

保留轨迹、检查结果、写入适当记忆，并为下一轮提供反馈。

一个实用判断：如果系统只能“回答”，它更像助手；如果它能围绕目标循环使用上下文和工具，并在边界内完成任务，它才接近 Agent。

Frequently confused

知识库、Skill、MCP：不是同一类东西

记住这个区分就够用：知识库告诉 Agent 知道什么；Skill 规定 怎么做；MCP 处理 怎么连。

用一句话分辨

RAG
一种把外部资料取回来放进当前上下文的方法。它不是知识库本身。
Skill
可复用的任务包：说明、流程、模板、脚本和资源。它可以规定何时检索、何时调用工具。
MCP
开放协议，标准化应用与外部工具、资源和提示词的连接；它不替代业务 API。
A2A
让不同 Agent 之间通信、委派和协作的协议。简单说，MCP 偏“接工具”，A2A 偏“找同事”。
Workflow 与 Agent
Workflow 的步骤主要由代码预先规定；Agent 会在边界内动态决定下一步。实际系统常混用两者。

From research to production

研究结论如何落到工程里

论文提供机制和可比实验，工程框架提供实现形态，云平台提供运行和治理能力。三者缺一块，系统就容易偏科。

推理与规划

ReAct 把“思考”和“行动”交替，Tree of Thoughts 处理需要搜索和回溯的问题。

  • 生产上先从短循环和明确停止条件开始
  • 规划不是越长越好，先保证可执行和可验证

检索与记忆

RAG、Self-RAG、MemGPT 提醒我们：上下文不是越长越可靠，选择与压缩同样重要。

  • 检索结果要有引用和新鲜度
  • 记忆需区分事实、偏好和暂态执行信息

工具与协议

Toolformer 研究“何时调用工具”；MCP 和 A2A 把连接与协作变成可互操作的接口。

  • 工具描述、参数校验、权限范围同等重要
  • 对有副作用的动作设置审批或确认

可观测与评测

AgentBench、GAIA、WebArena、SWE-bench 说明：最终要评的是在环境中完成任务，而不是单次回答像不像。

  • 记录轨迹、工具输入输出和版本
  • 离线样本集 + 线上人工反馈形成闭环
