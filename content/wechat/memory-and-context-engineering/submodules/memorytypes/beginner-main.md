# 记忆类型与画像：别把所有过去塞进一个抽屉

![记忆类型与用户画像封面](./assets/memorytypes-cover.png)

项目入口：[AI Agent 知识图谱仓库](https://github.com/Jennifer123www/ai-agent-knowledge-map)。本篇回答“**一条信息用来做什么**”，不负责替每条记忆制定写入事务；后者在“记忆写入与更新”里展开。

小林在报销助手里留下四种线索：这笔票据已经识别、上次报销因缺附件被退回、他多次明确希望中文简洁回答、今天的报销制度刚更新。四句话都与“小林”有关，存放与使用方式却不该一样。系统若把它们统统贴上“用户记忆”标签，明天可能把旧制度当新规则，或者把一次退单当成小林长期的个人特征。

## 一、分类先看用途，不看数据库名

常见说法里，**工作记忆**服务当前任务，**情景记忆**保留曾发生的经历，**语义记忆**保存经过验证、可能跨情境复用的事实，**用户画像**组织经允许且有用的偏好或约束。这是一种面向产品设计的分类口径，不代表每类都必须建一张表，也不代表四类完全互斥。

![四种信息用途并列](./assets/memorytypes-taxonomy.png)

这里要特别澄清：用户画像不是与语义记忆完全平行的“人脑第四种记忆”。它更像产品对某些用户相关事实和偏好的**受控表示**：字段、来源、授权、适用范围、删除入口，都应清楚。有些画像偏好本身也可看作语义信息；分类是帮助决定用途和治理，不是考一套永远唯一的标签答案。

“今天制度更新”则可能**不该成为小林的个人记忆**。制度有发布方、生效日期和适用范围，应从知识库或业务系统取得。分类的第一步不只是挑抽屉，还包括问“要不要放进这个人的抽屉”。

分类名称也不是产品之间通用的接口契约。有的系统把“工作记忆”叫会话状态，有的把“语义记忆”表示成带来源的事实字段；同名术语的保存范围可能完全不同。评审方案时，先要一条真实记录和一次读取请求，看它的来源、寿命与权限，别只看架构图上的标签。

## 二、工作记忆管当前这笔事

“票据已识别，等待核对制度”是本次报销的工作信息。它让助手中断后知道该从哪步继续，也可以包含已调用工具、待确认字段和当前草稿。任务结束后，它可以按业务规则归档或过期，**不该默认变成跨会话偏好**。小林下个月上传新票据时，系统不能因为上次停在“待核对”就说这次也已识别完成。

工作记忆在 AI Agent 里常表现为任务状态或可恢复的检查点。名称容易让人想到模型脑子里有一个不断亮着的小抽屉；实际可能是外部数据库里的结构化状态，再按需送进模型当前输入。存储在哪里不是分类依据，**它服务哪个时间范围与任务**才是。

如果一个正在进行的报销任务跨过两天，工作记忆仍可能保留；“短期”不等于必须当天清空。更准确的问题是：任务是否仍活动、状态是否可信、制度等外部事实是否需要重查。详细恢复机制留给短期状态那篇。

若小林在关闭页面前说“先别提交，我还要补附件”，这句话需要进入当前任务约束；恢复时它应拦住提交动作。等任务结束，它又不应变成小林“永远不允许自动提交”的长期偏好。**信息的内容相同，作用域不同，后续行为就不同。**这正是工作记忆值得单列的原因。

## 三、情景记忆记录发生过的事

“上次因缺附件被退回”是一段有时间、有事件、有结果的经历。它可能帮助助手在小林再次准备报销时提醒“请核对是否附齐资料”，但必须能追溯上次是哪笔、退回原因为何、此刻是否还相关。若退单只是制度临时故障，不能据此推断“小林经常漏附件”。

![观察与反思进入记忆流的原理图](./assets/memorytypes-principle.png)

*依据 [Generative Agents](https://arxiv.org/abs/2304.03442) Figure 5–6 改绘：观察与反思进入记忆流，再按情境取回。本文的“工作／情景／语义／画像”分类是教学延伸，不是论文原图的四个标签。*

论文里的模拟智能体会记录观察，再按当前情境检索相关经历；部分经历还能形成更高层反思。这个设计说明“曾发生的事”可以影响后续行动，同时也提醒我们区分**原始事件**与**从事件推出来的判断**。反思可能有用，但推断错了也会被反复引用。生产系统不应让一次退单自动长成“小林不认真”的长期标签。

如果助手想用上次退单经历提醒小林，可写成“上次这笔报销曾因附件缺失退回，是否要核对这次附件？”并附上可查看的原任务。不能写“小林一向漏附件”，因为那是从单个事件扩展出的无依据判断；也不能把退单经历当作这次票据不真实的证据。事件有边界，推论也要有边界。

## 四、语义记忆保存什么，什么应交还权威来源

语义记忆通常指相对稳定、经过验证、可在不同任务里使用的事实或概念。例如团队明确确认某个内部缩写的含义，后续写文档时可复用。但在报销场景里，员工职级、额度上限、制度版本虽然看着像“稳定事实”，仍可能变化，且有更权威的系统负责维护。**有事实味道，不等于适合复制进 Agent 的个人记忆。**

可以让记忆保存“该去哪类系统查这项事实”的线索，却不应让一条旧额度长期替代正式制度。若小林问“今天这张票能报吗”，先查身份、票据和生效条款；不能因为历史对话曾出现某个额度，就把它当今天的事实。把事实的**原始来源**与**方便查找的索引**分开，是避免陈旧答案的基本功。

情景与语义有时可以相互转换：多次退单经历经过核查，或许能总结出“这个流程通常需要某附件”；但总结仍需证据、适用范围和确认，而不能把统计上的“常见”写成对小林的固定特征。分类不是自动抽象流水线。

再看一个对照：小林说“我们组把‘出差单’叫‘行程单’”，这可以是有出处的术语说明；系统从组织词表查到“行程单”的正式字段定义，则应以词表为准。前一句是个人陈述，后一句是业务来源。即使文字几乎一样，回答时也要知道哪一个更权威、何时更新过。

## 五、用户画像究竟应该是什么

小林多次明确说“中文、简洁、先给结论”，这是有明确用途的表达偏好。若产品允许跨会话保存，可以在画像中用少量字段表示，并让小林查看、更正和删除。画像的目标是让助手在相关任务里少问几句，而不是尽可能收集更多个人细节。

![一次经历与受控画像的差别](./assets/memorytypes-profile.png)

一次报销被退回是经历，不应塞进“用户常犯错”这类画像标签；一次在上海出差也不等于小林长期居住上海。更不能从语气、健康、收入等敏感线索做无依据的推断并长期保存。**画像要受目的限制**：写进度邮件可能用到语言偏好，核对票据金额不应让偏好影响金额真伪。

用户画像与权限治理也有关。保存不代表所有 Agent 都能读取；相同组织的同名用户更不能共享画像。模型看到的名字是文本，真正的读取范围要由身份与租户控制。

设计画像字段时，还可以问它是否需要**明确的退出入口**。像默认语言这样能让用户直接检查和修改的偏好，相对容易管理；“可能比较焦虑”这类系统推测既不稳定，也可能造成不公平对待，不该因为字段库里有空位就填进去。字段越少，越容易向用户讲清为什么要留。

## 六、一条信息可能有多重标签，但去向仍要明确

“小林上次退单，原因是缺附件”既是一个事件，也包含“当时缺附件”的事实。如果未来只为了提醒补附件，可从有出处的事件里生成一条临时提示；没必要复制成三份互相难以删除的记忆。若经过人工确认后形成一条团队流程知识，那也应放在流程或知识库里，而非挂在小林画像下。

![从候选信息到去向](./assets/memorytypes-routing.png)

实际分类可以问四个问题：这条信息为**当前步骤**服务，还是未来会反复用？它是**发生过的事件**，还是已核的稳定事实？它关乎**用户偏好**，还是业务权威数据？如果保存，谁能看、何时退出？同一条候选可以带多个标签，但最终用途、读取范围和保留规则必须落地。

若分类器对某条信息没有把握，不必强迫它在四个标签中猜一个。可以标为“待确认”或“不保存”，留给用户或规则补充。错误写入长期库的代价，通常高于少记住一条还不确定的偏好；尤其在涉及身份、资金与权限时，这种克制很实际。

短比喻是收纳柜：票据进度放“正在办”，退单经历放“发生过”，偏好放“经同意的设置”；制度原文不放这个人的柜子。说完仍回到小林：分类是为了避免下一次回答拿错信息，不是为了让柜子看起来整齐。

## 七、分类错了会产生怎样的具体错误

把任务进度当长期偏好，新任务就可能被旧状态带偏；把一次经历当用户画像，会让系统反复做人格化判断；把正式制度当个人语义记忆，制度更新后仍引用旧额度；把明确偏好当一次性聊天，跨会话又得让用户重复交代。四种错误的修法不同，不能统一叫“记忆效果不好”。

![四个反例测分类边界](./assets/memorytypes-test.png)

让测试样本也对应这些错：临时出差城市应留在本次任务；一次退单保留事件与出处而非性格标签；制度上限回权威系统；语言偏好经允许后可跨会话使用。评测时先标注预期类别和预期**去向**，再看模型或规则把它放到了哪里。仅看最终回答能不能用，可能漏掉被错误保存却尚未暴露的风险。

测试集还应故意放进混合句，比如“我常用中文写报销说明，但这次请发英文邮件”。正确结果可能是长期偏好仍为中文，本轮邮件用英文；若分类器把后半句也写成永久偏好，下一次任务就会露馅。分类评测因此要跨两个以上会话，而非只看第一次提取是否像样。

## 八、分类之后还要有人把关

分类只是起点。它不负责替你判断小林是否同意长期保存，不负责旧偏好如何覆盖，也不能保证删除已传到缓存和索引。这些分别属于写入更新与记忆治理。最可靠的系统会给每条保存信息留下来源、用途、有效性和退出机制；无法说明这些，就宁可先把候选留在短期任务里，不急着升成长期记忆。

所以记忆类型这篇的记忆点很简单：**先问这条信息将来拿来做什么，再决定要不要存、放在哪里。**“都是关于同一个人”并不是足够的分类理由。
