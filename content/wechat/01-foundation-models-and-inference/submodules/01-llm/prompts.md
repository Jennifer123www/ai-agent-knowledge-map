## 1.0.0 面试副文专属图解

面试副文与主文共用事实口径和视觉系统，但不重复铺陈同一套图。本版保留自注意力、采样和证据核对三张必要共用图，并新增四张承担面试判断任务的图：成本预算、结构与事实边界、三类缓存对照、评测矩阵。四张图均使用内置图像生成工具完成，输出为 1536×1024 PNG，并已逐张核对中文、英文专有名词、示意数字和箭头关系。

### `llm-token-cost.png`

- 用途：回答“为什么不能按字数估计输入成本”，把切分机制与完整请求预算放在同一张图中。
- 结构：会议通知原文向下连接 token 片段、示意编号与向量；下半部展示系统指令、历史消息、工具定义、检索材料、当前输入和预留输出。
- 关键边界：分词与编号只作示意，不冒充某个真实模型的精确结果；结论写明“成本和窗口按目标模型实测，不按汉字估算”。
- 颜色：蓝色为原始输入，青绿为内部转换，梅红为已占用预算，铁锈橙为预留输出。
- 禁止项：不写固定的汉字—token 换算比例，不使用左侧通高装饰竖条、传统三列表格、随机小字、Logo 或水印。

### `llm-structured-truth.png`

- 用途：回答“为什么合法 JSON 仍可能写错事实”。
- 结构：同一份候选 JSON 依次通过结构校验、证据核对和正文一致性三道检查；用旧时间和无回执的 `sent` 展示“类型合法但事实不成立”。
- 必须出现：`required / type / enum`、最新要求“16:00—17:00、线上、链接待补、仅草稿”，以及修正后的 `draft_only`。
- 结论：“Schema 约束形状；证据与回执决定值能不能成立。”
- 禁止项：不把结构通过画成最终成功，不使用泛化四格流程、机器人、盾牌、Logo 或水印。

### `llm-cache-comparison.png`

- 用途：比较 `KV Cache`、前缀缓存和结果缓存，避免把三者都说成“复用上次答案”。
- 结构：三条独立泳道。第一条表现同一次生成中追加 token 并读取已有 K/V；第二条表现共同系统指令与固定资料分叉到会议 A、会议 B；第三条表现旧结果被误用于新请求的风险。
- 必须出现：预填充、K/V 块、显存代价、前缀一致与租户隔离、旧时间风险。
- 结论：“KV Cache 省同轮重算；前缀缓存省共同预填充；结果缓存复用最终答案。”
- 禁止项：不得画成三步串行流程，不暗示缓存取消自回归依赖。

### `llm-evaluation-matrix.png`

- 用途：回答“怎样设计可比较的模型评测”，让场景、字段判据和错误归因同时可见。
- 结构：上半部为普通改期、旧新冲突、链接缺失、后来补入链接四张场景卡；每张都检查时间、方式、链接和动作状态。下半部统计旧值误用、缺值编造、无回执却声称完成、字段与正文矛盾，并列出公平比较条件。
- 示意数值：错误次数仅用于解释分类统计，不代表真实实验结果。
- 结论：“严重错误单列，不能被文风分数平均掉。”
- 禁止项：不把单条成功样本画成评测结论，不用装饰性排行榜或没有分母的综合分。
