Research-backed interview guide

AI Agent 面试知识图谱

这不是“背名词清单”。它把面试中反复出现的 Agent 问题，组织成可说明原理、可比较取舍、可落到工程指标的答案。目标是让你的回答既有技术骨架，也能经得起一句“那上线后怎么做？”的追问。

使用方式：先看总览和答题结构；每次只练一个主题。进入下钻页后，按“原理 -> 答题点 -> 记忆点 -> 图解 -> 追问”完成一题。能讲清边界和指标，比把框架名念得像菜单更有说服力。

Answer structure

把答案讲成一个有工程判断的闭环

多数技术面不只检查“你知道定义吗”，还会继续问为什么这样设计、何时不适用、如何衡量、失败怎么办。下面四步可以用于大部分系统设计题。

01 / 定义先立边界

一句话说明概念解决什么问题，并区分最容易混淆的相邻概念。

02 / 结构再讲机制

用输入、处理、输出画出主链路。避免一上来钻进实现细枝末节。

03 / 取舍说明何时用

给出适用场景、代价和不适用条件。面试官通常在这里判断工程经验。

04 / 证据落到生产

说清权限、失败处理、评测指标、追踪与回滚。答案因此从“知道”变成“能做”。

Frequency map

当前高频考点如何连接

公开题库在基础、RAG、Agent、工具与 MCP、记忆、评测、安全、系统设计等主题上高度重合；协议和生产文档帮助我们校准每题应回答到什么深度。

建议准备顺序：先掌握主链路（模型、RAG、Agent、工具），再准备生产问题（评测、安全、成本），最后用一个真实或模拟项目把它们串起来。

Memory aids

三种答题记忆法

记忆点不是口号。它的作用是在紧张时把回答拉回工程结构，避免遗漏边界、取舍和验证手段。

定义 - 结构 - 取舍 - 证据

适用于“请解释 X”“怎么设计 X”。每一段至少一句，复杂题再展开。

先单体，后协作

适用于 Agent 与多智能体题：先证明单 Agent + 工具不够，再谈分工、通信和验收。

检索 - 生成 - 验证

适用于 RAG、工具和生产题：先拿依据，再生成或执行，最后用规则、测试或人工验证。
